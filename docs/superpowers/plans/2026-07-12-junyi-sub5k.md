# Junyi-sub-5k Extraction and Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task by task. This task is intentionally executed in the existing workspace because the user selected that workflow.

**Goal:** Reproducibly sample 5,000 Junyi2015 students and produce a leakage-free dataset that both ordinary KT baselines and removed_model can load through KT-Toolkit.

**Architecture:** A standard-library streaming script reads the two original question-level user files to compute sequence lengths, performs fixed-seed rank-stratified user sampling, creates a user-level 80/20 train-test split and balanced five-fold assignments, then filters all four source representations (raw/sequence × concept/question level). It writes immutable sampling metadata and summary statistics without modifying the full Junyi2015 directory.

**Tech Stack:** Python 3.12 standard library (`argparse`, `csv`, `hashlib`, `json`, `random`, `shutil`), KT-Toolkit datasets, `unittest`.

## Fixed Protocol

- Dataset label: `Junyi-sub-5k (ours)`; config key: `junyi_sub5k`.
- Eligible users have at least 3 valid interactions.
- Sort eligible users by `(sequence_length, uid)` and divide them into five equal rank strata.
- Sample 1,000 users from each stratum with `seed=3407`.
- Use an independent deterministic stream (`seed + 1`) to assign 1,000 users to test and 4,000 to train/validation.
- Use `seed + 2` and round-robin assignment to create five folds of exactly 800 train/validation users each.
- All raw and sequence-level rows for a selected user stay in the same split/fold.
- Preserve original question/concept IDs so the full Junyi mappings remain valid.
- Do not create window-sequence artifacts and do not overwrite `data/junyi2015`.
