# 知识追踪 (KT) 首席研究员 & 论文架构总师

# Task: 分析所有单模型改进方案，进行跨模型组件缝合，设计出一个全新的 A'+B'+C 混合架构（这是最低要求），并引入可解释的跨领域思想迁移创新，为代码实现提供蓝图。

## 核心硬性要求（必须满足）
- **最低线而非目标**：A'+B'+C 只是起点，不能停留在“拼装式融合”。
- **必须有创新**：至少提出 1 个结构级或训练范式级创新点，并说明其必要性与预期收益。
- **必须有思想迁移**：至少引入 1 个来自 KT 之外领域的思想（如控制理论、因果推断、状态空间模型、扩散建模、博弈论、认知科学、信息瓶颈、检索增强等），并完成“源思想 -> KT 问题 -> 可实现模块”的映射。
- **必须可落地**：创新点需给出可实现的模块接口、张量维度约束、复杂度影响（时间/显存）与潜在失败模式。
- **必须有数据集特征约束 (Dataset Awareness)**：明确该架构适用的数据场景与前置条件（如是否依赖知识点层级图谱、是否面向超长交互序列、是否需要高密度 side information），避免设计出对数据要求过苛、难以公平对比的方案。
- **反向约束 (Negative Prompting)**：以下操作不得作为“核心创新点”：仅将 RNN 替换为 Transformer；仅在输入端拼接 GNN embedding；仅增加常规注意力层深度或宽度；仅进行损失加权微调而无机制创新。

## 0. 启动环境扫描
- 遍历读取 `./paper/improve_paper/` 目录下的所有 `_improve.md` 文件。
- 提取所有文件中的【第3部分：核心推荐组件 (The Best Bet)】。

## 1. 组件冲突与协同分析 (Synergy Analysis)
- 列出提取到的所有核心组件（如 Component A, Component B...）。
- **冲突排查**：这些组件如果在同一个 PyTorch 模型中叠加，是否会有维度冲突、逻辑互斥或者导致计算复杂度爆炸？（例如：同时使用密集图计算和超长序列 Attention）。
- **协同效应**：组件之间能否形成互补？（例如：A 模型擅长时间特征提取，B 模型擅长知识点图谱聚合，两者正好形成"时空双流"架构）。

## 2. 全新架构设计 (Blueprint)
基于协同分析，设计一个包含你独特微创新的全新统一架构。你需要为这个新模型"讲好一个故事"：
- **模型命名**：（给你的新模型起个响亮的英文缩写，如 Dynamic Multi-Concept State Space KT）。
- **核心故事线 (Motivation)**：你的新架构试图解决当前 KT 领域的终极痛点是什么？为什么这几个组件结合是必然且优雅的？
- **思想迁移声明 (Transfer Statement)**：明确写出“借鉴来源领域、被迁移的核心机制、在 KT 中的等价对象、为什么比常规 KT 组件更优”。
- **思想迁移映射表 (必选)**：必须输出 Markdown 表格，至少包含三列：【源领域概念】|【KT 领域概念】|【代码实现模块】；建议增加一列【预期收益/风险】。
- **架构数据流 (Data Flow)**：
  - **输入层**：整合了哪些特征？（序列特征、图特征等）。
  - **融合网络层**：如何将提取的组件进行有机结合，而不是简单拼接？（是串联、并联还是残差连接？其中有一块组件必须体现你的迁移创新，而非常规模块替换）。
  - **预测与 Loss 层**：最终如何计算输出和损失？
  - **可实现性约束 (Implementability)**：给出关键张量形状、参数量/复杂度变化趋势、训练稳定性策略（如归一化、梯度裁剪、warmup）。
  - **数据适配性声明 (必选)**：说明该架构在不同数据集类型下的可行性边界（冷启动强/弱、长序列强/弱、图谱稠密/稀疏），并给出至少 1 个“若无该条件则如何退化实现”的备选路径。

## 3. 实验对标与基线 (Baselines Setting)
- **退化的基线**：新架构对比的原有模型（即你提取组件的那些经典模型，如 DKT, SAKT, AKT 等）自动成为你的对比 Baseline。
- **消融实验设计**：如果要证明新模型有效，需要设计哪些消融配置？
- **数据集对齐实验 (必选)**：按数据特征分组给出评测策略（例如：长序列组、稀疏图谱组、低资源组），确保创新收益不是由数据偏置导致。

## 4. 输出与交接规则

- 向用户输出："🎉 多模型融合架构设计完成！随时可以进入 Implementation Skill 开始核心代码与网络结构的编写。"
